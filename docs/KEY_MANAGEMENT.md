# Key management

`seal keygen --out PATH` generates an Ed25519 key using the operating-system randomness provider exposed through `ssh-key`'s `getrandom` feature. It writes an encrypted Seal private-key file to `PATH` and a public OpenSSH key to `PATH.pub`, and fails if either file already exists. The default prompts twice for a passphrase. `--passphrase-file FILE` reads one UTF-8 line, with an optional final LF or CRLF; it is intended for controlled automation and the file should be protected and removed by the caller. Passphrases must contain 12 to 1024 bytes.

The Seal private-key container uses Argon2id v19 (64 MiB, 3 iterations, 1 lane, 32-byte output) and XChaCha20-Poly1305 with random 16-byte salt and 24-byte nonce. The fixed header is authenticated as associated data. There is no plaintext-key fallback. A wrong passphrase or altered ciphertext is rejected. Signing commands accept `--passphrase-file` or prompt once. Unix creates the private file with mode `0600`; Windows creates it without sharing, applies a protected DACL for owner rights, SYSTEM, and Administrators before writing ciphertext, then reads back and checks the DACL. These controls protect the file at rest against other ordinary local accounts; they do not protect against an already compromised account, administrator/kernel access, weak passphrases, memory inspection, or unsafe backups. Sensitive buffers are zeroized where supported, but the Rust/OpenSSH parser may make internal copies that Seal cannot promise to erase.

Public keys use the OpenSSH `ssh-ed25519` representation. Fingerprints use OpenSSH SHA-256 fingerprint formatting. Verification always requires an explicit `--public-key`; a key carried in the signature record is only an identity hint and must match the supplied key exactly. Obtain the expected fingerprint through an independently authenticated channel.
